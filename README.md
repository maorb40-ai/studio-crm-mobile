CRM מתי - אפליקציית אנדרואיד
===============================

אפליקציית נייד (React Native, אנדרואיד בלבד) שמתחברת לשרת ה-CRM (F:\studio-crm)
ומאפשרת לעבוד עם המערכת גם בלי אינטרנט: כל הנתונים (לקוחות, ביקורים, הצעות
מחיר, חוזים, קבלות, הוצאות, משימות, גלריות, המלצות, ציוד, שיווק, ספר טלפונים
ועוד) נשמרים גם על המכשיר, ומסתנכרנים אוטומטית עם השרת בכל פעם שיש רשת.

**מצב נוכחי (שלב א'):** לקוחות, ביקורים ומשימות - צפייה ועריכה מלאה, כולל
בלי אינטרנט. שאר המודולים - צפייה מלאה בלבד (עריכה תתווסף בהמשך). כל
המודולים מוצגים כבר עכשיו, מסונכרנים במלואם.


למה אי אפשר לקבל כאן קובץ APK מוכן?
------------------------------------
הסביבה שבה נכתב הקוד הזה היא ענן מבודד בלי גישה לשרתי Google (Android SDK)
ובלי אפשרות להתקין את כלי הבנייה של אנדרואיד. לכן נמסר כאן פרויקט קוד מלא
ומוכן, ויש שתי דרכים להפיק ממנו קובץ APK בפועל - בחרו את מה שנוח יותר:

**דרך א' - בענן, בלי להתקין שום דבר על המחשב (הכי פשוט):** בתיקייה
`.github/workflows/build-apk.yml` יש כבר הגדרה מוכנה שגורמת ל-GitHub לבנות
את ה-APK אוטומטית בשרתים שלו. הצעדים בקצרה (הרחבה למטה): פותחים חשבון
GitHub חינמי -> יוצרים repository חדש -> מעלים לתוכו את כל תוכן התיקייה
הזו (גרירה בדפדפן, בלי צורך בפקודות) -> ממתינים כ-10 דקות בלשונית Actions
-> מורידים את קובץ ה-APK המוכן.

**דרך ב' - במחשב, עם Android Studio:** מתאימה אם רוצים גם סביבת פיתוח
מקומית להמשך עבודה על האפליקציה. לוקח כ-10-20 דקות בפעם הראשונה (רוב הזמן
זה הורדת Android Studio עצמו).


### דרך א' בהרחבה - בניית APK בענן דרך GitHub (בלי התקנות)

1. נכנסים ל-https://github.com/signup ופותחים חשבון חינמי (אם עוד אין).
2. אחרי הכניסה, לוחצים על "+" למעלה מימין -> "New repository". נותנים לו
   שם (לדוגמה `studio-crm-mobile`), משאירים "Private" מסומן (השמירה על
   פרטיות המידע), ולוחצים "Create repository".
3. בעמוד של ה-repository החדש, לוחצים על "uploading an existing file"
   (או "Add file" -> "Upload files").
4. **חשוב:** גוררים לתוך הדפדפן את **תוכן** התיקייה `StudioCrmMobile`
   (את כל הקבצים והתיקיות שבפנים - App.tsx, android, src, package.json
   וכו') - לא את התיקייה `StudioCrmMobile` עצמה כתיקייה יחידה. אפשר לגרור
   כמה קבצים/תיקיות יחד. ה-node_modules לא כלול בחבילה בכלל (זה בסדר,
   GitHub לא צריך אותו).
5. גוללים למטה, לוחצים "Commit changes".
6. עוברים ללשונית "Actions" למעלה בעמוד ה-repository. אמורה להופיע ריצה
   בשם "Build Android APK" עם עיגול צהוב מסתובב (רץ) שיהפוך לירוק ✓ אחרי
   כ-10 דקות (אם משהו נכשל, יופיע X אדום - ראו הערה בסוף).
7. לוחצים על הריצה שהסתיימה בהצלחה, גוללים למטה לחלק "Artifacts", לוחצים
   על `StudioCrmMobile-debug-apk` - זה מוריד קובץ ZIP קטן שבתוכו קובץ
   ה-APK עצמו.
8. מעבירים את קובץ ה-APK לטלפון האנדרואיד (למשל דרך Drive/WhatsApp
   לעצמכם) ומתקינים (יידרש לאשר "התקנה ממקורות לא ידועים" בטלפון בפעם
   הראשונה - זה תקין, זו לא אפליקציה מחנות Play).

אם הריצה נכשלת (X אדום) - לרוב זו בעיית גרסה שקל לתקן; אפשר לשלוח לי צילום
מסך של השגיאה בלשונית Actions ואני אדריך מה לתקן.


דרישות מוקדמות (למי שבוחר בדרך ב' - Android Studio במחשב)
----------------------------------------
1. **Android Studio** (חינמי) - https://developer.android.com/studio
   בהתקנה הראשונה הוא גם מתקין את ה-Android SDK הדרוש.
2. **Node.js** גרסה 22 ומעלה - https://nodejs.org
3. חיבור אינטרנט תקין (להורדת החבילות - `npm install` מוריד כ-900 חבילות,
   וב-Gradle יש הורדה חד-פעמית של כלי הבנייה של אנדרואיד).


שלבי הבנייה
------------

### 1. התקנת תלויות ה-JavaScript

פותחים טרמינל (או Git Bash / PowerShell) בתוך תיקיית הפרויקט הזו ומריצים:

```
npm install
```

זה ייקח כמה דקות בפעם הראשונה.

### 2. פתיחה ב-Android Studio (מומלץ, הכי פשוט)

1. פותחים את Android Studio.
2. "Open" -> בוחרים את תיקיית `android` שבתוך הפרויקט הזה (לא את תיקיית
   השורש - את תיקיית `android` הפנימית).
3. ממתינים ל-"Gradle Sync" שירוץ אוטומטית (בפעם הראשונה זה יכול לקחת כמה
   דקות - מוריד את כלי הבנייה).
4. מחברים טלפון אנדרואיד עם כבל USB (עם "ניפוי שגיאות USB" מופעל בהגדרות
   מפתחים בטלפון), או פותחים אמולטור וירטואלי מתוך Android Studio.
5. לוחצים על כפתור ה-Run (המשולש הירוק) - האפליקציה תותקן ותיפתח ישירות
   במכשיר/באמולטור.

זו הדרך הכי מהירה לבדוק שהכל עובד. כדי לקבל קובץ **APK** ממשי לשיתוף/התקנה
ידנית, ממשיכים לשלב 3.

### 3. הפקת קובץ APK להתקנה ידנית

מתוך Android Studio: תפריט `Build` -> `Build Bundle(s) / APK(s)` ->
`Build APK(s)`. הקובץ המוכן יופיע ב-
`android/app/build/outputs/apk/debug/app-debug.apk` - אפשר להעביר אותו
ישירות לטלפון (למשל בהודעת וואטסאפ לעצמכם, או ב-Google Drive) ולהתקין.

לחלופין, משורת הפקודה (בלי לפתוח את Android Studio בכלל):

```
cd android
./gradlew assembleDebug
```
(בווינדוס: `gradlew.bat assembleDebug`)

הקובץ ייווצר באותו נתיב שצוין למעלה.

**הערה על APK "debug":** זה מספיק לחלוטין לשימוש אישי/פנימי בעסק (מה
שרלוונטי כאן). קובץ "release" חתום דורש הגדרת מפתח חתימה (keystore) - שלב
נוסף שרלוונטי רק אם מתכננים בעתיד לפרסם את האפליקציה בחנות Google Play.


התחברות לשרת מתוך האפליקציה
------------------------------
בפתיחה הראשונה של האפליקציה יופיע מסך כניסה עם שני שדות:

1. **כתובת השרת** - כתובת ה-ngrok הקבועה שכבר מוגדרת למערכת (אותה כתובת
   שמשמשת לגישה מרחוק מהדפדפן), או כתובת הרשת המקומית (LAN) אם משתמשים
   רק בבית/בסטודיו על אותה רשת WiFi כמו המחשב שמריץ את השרת.
2. **סיסמה** - אותה סיסמה בדיוק שמשמשת להיכנס לפאנל הניהול באתר (משתנה
   הסביבה `APP_PASSWORD`).

השרת (F:\studio-crm) צריך להיות פועל כדי שהאפליקציה תוכל להתחבר ולסנכרן -
בדיוק כמו גישה מהדפדפן.


מבנה הקוד (למי שממשיך לפתח)
------------------------------
- `src/api/mobileApi.ts` - קריאות HTTP לנקודות הקצה /api/mobile/* בשרת.
- `src/storage/localStore.ts` - "מסד הנתונים" המקומי (AsyncStorage, בלוק
  JSON לכל ישות - בכוונה בלי SQLite נייטיבי, כדי למזער תלויות בנייה).
- `src/sync/syncEngine.ts` - מנוע הסנכרון (push לפני pull, זיהוי
  התנגשויות, מיזוג מזהים זמניים -> מזהי שרת אמיתיים).
- `src/context/AuthContext.tsx` + `SyncContext.tsx` - מצב התחברות + סנכרון,
  זמינים לכל מסך.
- `src/screens/` - כל מסכי האפליקציה.
- `src/navigation/viewOnlyModules.ts` - רשימת המודולים לצפייה-בלבד; כדי
  להוסיף עריכה למודול נוסף, צריך גם לשנות אותו ל-canWrite:true בקובץ
  המקביל בשרת (`lib/mobileSync.js`, מערך SYNC_ENTITIES) ולבנות מסך עריכה
  ייעודי (בדומה ל-ClientsListScreen/TasksScreen).

כל הלוגיקה (localStore + syncEngine) נבדקה בהרצה אמיתית (לא רק נכתבה) -
כולל תרחישי יצירה/עריכה/מחיקה במצב לא-מקוון, ותרחיש התנגשות בין עריכה
באתר לעריכה במכשיר.


מגבלות ידועות בשלב הנוכחי
----------------------------
- עריכה מלאה זמינה רק ללקוחות/ביקורים/משימות. שאר המודולים לצפייה בלבד.
- אין עדיין מסך ייעודי לפתרון התנגשויות (הנתונים מגיעים ל-conflicts ב-
  SyncContext, אבל עדיין אין UI שמציג אותם ללקוח ומאפשר לבחור גרסה - כרגע
  השינוי המקומי פשוט ממתין בתור עד להחלטה עתידית).
- קובץ הבדיקה `__tests__/App.test.tsx` (שהגיע עם התבנית הרשמית) עשוי
  להיכשל בהרצת `npm test` כי הוא לא כולל מוקים ל-AsyncStorage/Navigation -
  לא משפיע על הבנייה/הפעלה של האפליקציה עצמה, רק על ריצת הבדיקות.
